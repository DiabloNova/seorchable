### 1-3: Make PostgreSQL transactions request-safe
```Read the root AGENTS.md first.

Task: Remove shared singleton transaction state from the PostgreSQL persistence adapter.

Target:
- `src/features/admin/infrastructure/persistence/postgres/index.ts`
- One focused regression test using the repository’s existing test convention

The current adapter contains transaction state on the singleton, including shared flags or operation queues. Replace that behavior with a request-scoped `PoolClient`.

Required behavior:

1. Lease one PoolClient per transaction.
2. Run BEGIN, tenant setup, queries, and COMMIT on that client.
3. Roll back on failure.
4. Release the client in `finally`.
5. Prevent concurrent requests from sharing transaction state.
6. Preserve existing repository interfaces and tenant-context checks.
7. Do not introduce mock or in-memory production persistence.

Add a deterministic test covering concurrent transactions and client release on both success and failure.
```
