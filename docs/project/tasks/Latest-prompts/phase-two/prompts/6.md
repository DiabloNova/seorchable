### 2-6: Implement password recovery
```Read the root AGENTS.md first.

Task: Implement secure password reset using the repository’s verified authentication and email architecture.

Target only:

- src/app/[locale]/forgot-password/*
- src/app/actions/*
- Existing auth repositories and services
- Existing token schema and migrations
- One focused password-reset test

Required behavior:

1. Accept an email address without revealing whether the account exists.
2. Create a single-use, expiring reset token.
3. Store only a secure token hash where supported.
4. Send the reset link through the existing email provider.
5. Never log or return the raw token.
6. Validate the token server-side.
7. Require a strong replacement password.
8. Replace the password hash transactionally.
9. Revoke existing sessions after password reset.
10. Reject expired, reused, malformed, and unknown tokens.

Do not implement a fake email flow. Do not add a new provider. If the required schema or provider contract is missing, report BLOCKED.

Verification:

pnpm exec tsc --noEmit
pnpm lint
pnpm build
pnpm exec drizzle-kit generate
git diff --check

Run focused tests for unknown email, valid reset, expired token, reused token, password replacement, and session revocation.

```
